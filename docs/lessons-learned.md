# 实战复盘：问题 → 解决方法

来源：2026-11-09 一次真实的 6 天环太湖自驾规划（苏州往返，3 人，11/10–11/15）。每条记录当时的现象、根因与最终解法。

> **范围说明**：本 skill 与原 skill 保持同一思路与 6 件契约，仅天气图三级阶梯（第 5 条）与图例投影修复（第 8 条）进入了 skill；其余条目是项目过程记录，不属 skill 范围。

## 1. 行程超出官方预报窗，天气结论无从采样

- **现象**：原定 11/20–11/24 出发，11/09 制作时超出中央气象台 7 天窗，`forecast_png` 只能放白底占位，verdict 无从写起。
- **解法**：verdict 统一写占位 `待 11/13 后官方图采样`，天气 PDF 明示"占位版"；中期参考（Open-Meteo / ECMWF IFS 16 天）只作附页，标注 `中期参考·非 go/no-go`。
- **去向**：过程记录（本复盘），不入 skill 范围；skill 原版已要求"仅在预报窗内做天气环节、日期定稿后再出 PDF"。
- **后续**：用户把行程改到 11/10–11/15 后正好落进 7 天窗，才有真正的像素采样结论。

## 2. 改日期后 `out/` 混出 8 个文件，违反 6 件契约

- **现象**：5 天 4 晚 → 6 天 5 晚整包重做后，`out/` 同时存在 1124 与 1115 两代 xlsx/PDF/annotated 图。
- **根因**：重做只"新增"不"清理"。
- **解法**：先 `Copy-Item -Recurse out out_{旧日期}_final` 备份，重跑后按 glob 删除旧日期残留，复检 `len(out) == 6`。
- **去向**：过程记录（本复盘），不入 skill 范围；原 skill 的 *Version discipline* 已要求备份后再生。

## 3. 官方降水图下载：URL 规律与时次/时区

- **现象**：`nmc.cn` 页面是 JS 渲染，`findstr` 抓不到图链；拿到图后 `13Z` 起报对应北京 21 时，差点写成"UTC 午夜"。
- **解法**：
  - 从 HTML 源码用正则抽 `image.nmc.cn/product/...` 直链（`fetch_regional.py` 的做法）。
  - NMC STFC 全国 24–168h 降水图规律：`SEVP_NMC_STFC_SFER_ER24_ACHN_L88_P9_{日期}{时次}00{lead}.JPG`，lead = 02400…16800；最高温用 RFFC `SNWFD_ETM` 系列。
  - JPG 转 PNG 后入 `src_dir`，横幅写 `model + 起报时次 + 时区换算 + 红线=当天行程`。
- **固化**：URL 规律与时次换算为过程记录（本复盘）；"自行下载官方图并记录 model/init/时区"原版 `weather.md` *Sources* 已有。

## 4. 线性 bbox 校准在锥投影下偏了 90 像素

- **现象**：按 `bbox_px + 经纬度范围` 线性映射，太湖落在 (633,392)——采样到的是东海；上海锚点全对不上。
- **根因**：全国图是锥投影，图框经纬网不是线性的，区域尺度上线性外推误差可达 ~90px。
- **解法**：画 50px 网格（`grid.png`）找地标（上海湾、南京、杭州湾）重钉；最终把 6 个站点像素写进 `weather.xy_override` 复用于每一页。
- **去向**：过程记录（本复盘）；原版 `weather.md` 已要求"zoom 裁剪确认落陆 + `xy_override`"，锥投影偏差是其成因补充。

## 5. 全国图上太湖只有 ~20px，裁剪放大也看不清

- **现象**：用户先后两次反馈看不清——先要求"别用全国图"，裁到华东 `540,260,770,480` 放大 4 倍后仍是锯齿马赛克。
- **根因**：源图 849×718，物理分辨率不够，插值放大不产生信息。
- **解法**：可读性阶梯第 3 级——**定位底图 + 官方采样填色**：
  - 底图换成行程区域矢量图（Natural Earth 外框，`118.8–122.2E / 30.2–32.2N`，1600×1000，太湖/上海/杭州清晰可辨）；
  - 陆面填色 = 官方全国图在该点采到的色值（白 `#FFFFFF`=0mm、浅绿 `#A6EA90`=0-10mm，取自图例）；
  - 左下角保留官方图例 + 采样说明，横幅保留出处链，`weather._note` 记原图 URL/检索时间/采样方法；
  - verdict 一字不改——只换了底，没换数据。
- **固化**：`weather.md` → *Legibility ladder*；SKILL 第 7 条非协商项。

## 6. 没有江苏省 7 天降水成图——产品层级要如实记录

- **现象**：用户问"没有江苏省的天气预报图吗"。
- **排查结果**：NMC/CMA 无省级 7 天降水 JPG；CMA 区域模式降水只到 36h 且部分页面 404；城市页（`nmc.cn/publish/forecast/...`）有 7 天逐时表但是文本。
- **解法**：不伪造、不硬凑，把三级产品与各自局限写给用户；当前证据链仍是"全国成图采样"，城市表只作打包参考附录。
- **去向**："先记录目的地图源产品是否存在、缺失即报告"已入 skill（`weather.md` *Legibility ladder* 开头）；CMA 具体产品层级为过程记录（本复盘）。

## 7. 城市页比全国图"湿"，两个官方源打架

- **现象**：苏州城市页显示 11/14 有 `4.9mm/3h`，全国图同日太湖是 0–10mm/24h 档（浅绿）。
- **解法**：按非协商项，**go/no-go 以成图采样为准**；两个数都报给用户并说明口径差异，由用户知情。
- **去向**：过程记录（本复盘）；原版 `weather.md` "verdict 只来自采样" 已覆盖此裁决。

## 8. 图例文字与色块错位（投影坐标系混用）

- **现象**：地图图例文字整体偏出 swatch 列。
- **根因**：swatch 位置经 `g.pt()` 投影，文字 x 却用了投影前的图面坐标。
- **解法**：`tx_proj = tx * g.KX`（横轴比例），补丁并入 `build_maps.py`。
- **固化**：已入 skill——`scripts/build_maps.py` 代码修复（CHANGELOG 1.0.0 Fixed）。

## 9. PowerShell 中文输出半途崩溃

- **现象**：脚本文件已写出一半，最后 `print` 报 `cp1252 UnicodeEncodeError`；`python -c "…中文…"` 经 PowerShell 传参直接乱码。
- **解法**：每次运行前 `$env:PYTHONIOENCODING='utf-8'`、`$env:PYTHONUTF8='1'`、`chcp 65001`；含中文的逻辑一律写成 `.py` 文件再执行。
- **去向**：过程记录（本复盘）+ README 快速开始的一行提示，不入 skill 范围。

## 10. 横幅文案过长被裁切

- **现象**：天气页横幅 source 行太长，右侧被截断，出处反而看不全。
- **解法**：横幅只留 `model + 起报/发布时次 + 红线说明`，完整 URL/检索时间下沉到 `weather._note` 与手册封面。
- **去向**：横幅三行规范原版 `deliverables.md` 已有；本次为文案长度调整，属配置内容（过程记录）。阶梯第 2/3 级的出处要求见 `weather.md` *Legibility ladder*。

## 11. 路线版与多晚住宿的契约细节

- **现象**：改 6 天后出现湖州连 2 晚，需要 `D3/D4` 丸子（pill）；路线版副标题曾带具体日期。
- **解法**：多晚丸子由 `days[].stay` 自动派生（原版 `maps.md` Markers 已定义）；路线版副标题去日期、去价格，出图后按 `maps.md` 核单逐条读图确认（原版核单已有"路线版无日期"）。
- **去向**：规则均在原版 `maps.md`；本条为触发场景记录。

## 12. 交付前必须"像第一次看一样"读图

- 两次地图返工（东山标签串位、起点被裁、图例错位）都是靠逐条走 `maps.md` 核单发现的——核单不是形式，是唯一拦住"数据对了、图错了"的关口。
